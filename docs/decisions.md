## 关键语义

“可信度分流”针对历史提炼、分类与去重，不是对验收执行结果自动审核。验收报告只呈现执行者提交的结果与材料；结构校验不证明结论真实。

“Bug 状态”不包含修复生命周期。允许候选记录处置、版本替换、合并重定向、同步任务状态和验收执行状态，这些都是系统操作所必需的数据管理信息。

“跨项目合并”合并问题知识，不合并所有项目的具体触发事实。发生场景没有 open/fixed/closed 字段。每个场景保留项目、版本上下文、来源与证据。

“必验”是验收计划的覆盖要求，不是发布准入门槛。没有执行的必验项出现在报告中，报告不产生 release_allowed 等字段。

Bug 的“发现来源”描述该问题为何进入人工关注范围，不记录修复状态。人工报告必须有用户角色的原文证据；人工引导 Agent 检查必须同时保留用户引导和 Agent/工具发现证据。Agent 后续自行新增测试产生的失败不反向成为人工需求。

## 可调整工程默认值

以下由方案补齐，不冒充用户逐项确认：Node.js >=22、ESM、strict TypeScript、npm workspaces、MCP stdio、一个 npm 分发单元、Kysely 查询层及显式双后端迁移、stdio 只读日志写 stderr。

受控类型使用 UUID，不以名称为身份；项目匹配类型采用 ANY，去重时按全部候选类型做并集召回。类型层级只组织词典，不隐式扩大验收范围。

后台功能首版提供前台 worker（可由用户交给系统服务管理器运行），不自行安装系统服务或修改登录启动项。无模型配置时仅采集并排队，等待外部智能体领取分析任务。

CLI 默认交互可读，`--json` 使用版本化结构；写入和结果接收使用幂等键。默认列表页 50、最大 200，模型上下文有条目与 token 双重预算；这些数值以基准测试调整。

内置提供者默认 Chat Completions 结构化响应，兼容能力不足时采用 JSON 文本＋schema 校验，不凭“OpenAI 兼容”假定所有扩展均可用。Responses API 可作为同提供者的可选协议模式，首版不把其支持作为必要条件。
