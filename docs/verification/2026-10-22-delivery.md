## CLI、MCP、Skill 与完整闭环

- transports.test.ts 以真正 MCP SDK Client 启动 stdio 服务，与 CLI 交叉写读。两个后端分别验证分页、schema、冻结计划、追加结果、missing_evidence 一致错误、失败和 I0 未执行报告导出仍退出 0。没有模拟 MCP 连接代替握手。
- workflow.test.ts 在两后端从合成 Codex/Claude 历史，经手动/后台/lazy 同步、外部与内置分析、跨项目复用标准、类型保存、真实 Git 差异、智能体夹具执行 Node 操作并提交实际 stdout，到冻结双报告。内置路径的该 E2E 使用本地 HTTP mock；真实端点 smoke 独立记录。
- skill.test.ts 验证 Codex/Claude、用户/项目四种显式目录安装，幂等、冲突、保留无关文件、阻止链接越界。Skill 静态校验通过。另由本机 Codex CLI 以 `debug prompt-input` 验证产品 Skill 出现在 model-visible Skills 清单，未请求模型；Claude Code 与其他客户端/OS 的加载仍不据此认定。
- doctor.test.ts 验证合法模板、无 Key 的 external 路径、worker 状态、工具输入 schema、非法 JSON 与真实不可达数据库端口，诊断不回显密码或 Key。
- reports.test.ts 验证错误归属/修订、缺步骤与证据、幂等 attempt、执行版本隔离、旧有效结果保留、旧报告跨知识合并可读、双格式同源与不可信 Markdown 转义。RPT-006 补充验证全 not_applicable 不计通过及 failed/blocked/not_run 优先关系。

验收动作由智能体夹具调用其工具执行；产品只接收结果，不执行测试/浏览器/设备，不以材料内容判断结论正确。结构完整但不能证明通过的材料仍原样呈现供人审，没有自动审证、复验、审核分数或 release_allowed。

## 故障与恢复

模型认证/限流/超时/非法 JSON/预算耗尽；数据库真实连接终止、并发初始化、独立进程请求重放及旧租约；证据写入 ENOSPC 注入；实际 worker kill/restart；watcher `error` 故障注入后周期补扫仍发现新增分段；源文件丢失、替换、半条 UTF-8、损坏范围；缺失/篡改/越界证据均有检查。失败不推进分析完成点，事务不留下半套知识/关系/幂等记录，恢复可重试，pending 与来源不可用仍可见。注入 ENOSPC 没有实际填满磁盘。

## 平台兼容性与未验证项

Windows Node 24.21.0 的上述全量结果通过。Linux 以只读源挂载复制到独立 Docker 工作目录并干净 `npm ci`，安装编译工具与 Python，从源码构建 better-sqlite3 13.0.3；没有复用 Windows node_modules。宿主为 Docker/WSL2，两个 Debian 容器核实为 Debian GNU/Linux 12，Alpine 容器为 Node 24.21.0 Alpine；内核版本和资源计数分别保存在断言记录的 environment 中。typecheck、lint、format:check、build 和包安装均通过。

两组 Debian 首轮未配置 PostgreSQL，均为 95 通过、73 明确跳过、退出 0；随后接入本任务专用 PostgreSQL 16 测试库重新跑完整 169 项，两组均零失败、零跳过、无未捕获错误、正常退出。Alpine 第一次连接同一专用 PostgreSQL 16 测试库时暴露了镜像未安装 `git` 的 `spawn git ENOENT`，补齐 Git 后重新运行；当前代码在三个 Linux 环境均对包含 watcher error 恢复用例的 169 项全部通过。补跑验证真实 CLI/MCP 交叉写读、worker kill/restart、计划大批量分页、双向互导、实际 PG 连接终止与恢复，未调用外部付费模型。不同版本同时运行，耗时是该共享宿主环境的观测，不作为性能基准。

使用的公开镜像为 node:22-bookworm-slim（digest sha256:de170b39439eb0e5a3444ad7d60b015614a381e10fecae2e30ec9e735122f38d）、node:24-bookworm-slim（digest sha256:55fb5f5a527ea2c5c4a95f963e48ef90aa38c7b346054fdc8ee9957a2b55d205）与 node:24.21.0-alpine，通过现有公共镜像代理拉取。完整命令为在各独立 /work 目录配置合成测试专用 BUG_MANAGER_TEST_DATABASE_URL 后，执行 `npm run test:all -- --reporter=default --reporter=json --outputFile=artifacts/tests.json`。包含 watcher error 恢复用例的当前代码原始结果位于 artifacts/docker-current-node22、artifacts/docker-current-node24 和 artifacts/docker-current-alpine-node24；公开的仅为去除日志和绝对路径的断言摘要。

最终安装包包含当前 README、usage、operations 和 canonical Skill；Windows 与三个 Linux 环境均对文档更新后的内容再次完成临时消费者安装。Linux 三个环境的 tarball sha 相同，Windows 因打包文件序列化差异保留了独立 sha；四份快照不能互相替代平台验证。安装测试的临时消费者会自动清理；本轮 Linux 验证容器在保留工件后移除，镜像和独立 PostgreSQL 测试容器仍保留。

早期 Alpine / Node 24.21.0、better-sqlite3 12.11.1 从源码构建的组合曾真实失败：较大批量标准/并发计划用例中，原生 Statement 回收触发 Node `RemoveEnvironmentCleanupHook` 的环境断言并终止进程。GDB 栈经过 Statement 析构与 V8 GC；独立 Node（不经 Vitest）运行相同合成写入也能复现。根因与 Node 24.19+ 及旧驱动的清理路径相关，上游记录见 [better-sqlite3 #1515](https://github.com/WiseLibs/better-sqlite3/issues/1515) 与 [Node #65446](https://github.com/nodejs/node/issues/65446)。升级到使用 N-API 路径的 better-sqlite3 13.0.3 后，Alpine 在干净安装下完成全部 168 项并退出 0。旧失败、私有文本栈和诊断仅保留为历史根因证据，不代表当前依赖状态。

macOS、远程 GitHub Actions 矩阵及 Claude Code 真实 Skill 加载未执行。Windows 与 Debian/Alpine Linux 都已在本地运行当前 169 项双数据库测试和当前包安装；Codex CLI 0.163.0-alpha.10.2 已在 Windows 验证 Skill 发现，但不覆盖桌面交互选择行为或其他版本。CI 文件已配置三 OS × Node 22/24 及真实 PG 服务，并输出环境/JSON/包安装工件，但本仓库没有 remote，配置不等于 job 已运行。
