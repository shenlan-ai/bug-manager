# 安全边界复核与最终回归

本记录补充 2026-10-22 的完整交付快照，说明最后一次产品代码变更及当前可复核结果。OpenSpec change 当前为 51/53，不归档、不同步到正式基线，也不发布 npm。

## 本次产品变化

- `EvidenceStore` 在 `inbox` 或 `objects` 被替换为目录链接时，先验证解析后的真实路径仍位于配置的证据根目录内，再读取或写入对象；受管哈希子目录在创建后也会重新验证包含关系。
- Bug 场景指纹改为基于已解析的稳定 `bug_id`、项目/版本/描述/证据字段及来源段，不把调用方局部 `bug_ref` 当作身份。该规则与同一逻辑来源不重复附着的约束一致。
- 新增三个回归检查：T170 验证稳定场景指纹，T171 验证外部 `inbox` 链接被拒绝，T172 验证外部 `objects` 链接被拒绝。
- 后台 worker 在周期补扫间重新启用同一个 `history_sync` 作业，避免每 30 秒永久增加一条已完成的同步任务；中断作业仍沿用检查点恢复，新鲜度反映最近更新的采集结果。
- 证据有界读取要求实际读到的字节数严格等于读取前文件大小；读取过程中被截短的文件会返回 `invalid_evidence_size`，不会把较短内容当成完整对象。T173 使用确定性文件句柄回归覆盖该竞态。
